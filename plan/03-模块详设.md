# 03 · 模块详设

> 五个子命令的接口、数据结构、处理顺序、失败路径与测试点。所有数值口径引用 `data/README.md` §四；本文件不另立第二套。退出码语义见 §四.7 与 `src/mojibake_forensics/report.py`。

## 一、公共契约

### 1.1 输出形态

- **人读**：默认写 stdout，稳定、无颜色、无时间戳。
- **机读**：`--json` 输出规范 JSON（`sort_keys=True`, `ensure_ascii=False`, `indent=2`, LF, 结尾换行）。
- **错误**：结构化错误写 stderr；`--json` 时同时输出 `{"status":"error","code":...,"message":...}` 到 stdout（退出码 2 的坏输入除外：不写任何文件，stdout 只放错误 JSON）。
- **候选恒为列表**：任何单候选都包在 `candidates` 数组里，并带 `note`；禁止"已确定 / 正确编码是 / 修复成功"。

### 1.2 公共字段

```json
{
  "schema": "mojibake-forensics/1",
  "tool_version": "0.1.0.dev0",
  "python_version": "3.8.18",
  "status": "candidates | no_candidate | recovered | lost | not_mojibake | ok | error | not_ready",
  "notes": [],
  "criteria": {
    "encoders": ["utf-8", "..."],
    "decoders": ["utf-8", "..."],
    "max_depth": 3
  }
}
```

`criteria` 是"结论口径"的一部分：每次输出都必须带，提醒读者候选是"给定集合与链深下的全部无损可能"，不是事实真相。

### 1.3 链路结构 `Chain`

```json
{
  "path": [{"op": "encode", "codec": "cp1252"}, {"op": "decode", "codec": "utf-8"}],
  "path_string": "encode:cp1252>decode:utf-8",
  "depth": 1,
  "steps": [
    {"index": 1, "op": "encode", "codec": "cp1252",
     "input": "é›…", "output_hex": "65 C3 8B E2 80 A6", "ok": true},
    {"index": 2, "op": "decode", "codec": "utf-8",
     "input_hex": "65 C3 8B E2 80 A6", "output": "雅", "ok": true}
  ]
}
```

- `depth` = 链中 `decode` 的步数（`data/README.md` §4.2）。
- 字节统一大写十六进制、单空格分组。
- `steps` 由 `paths.py` 构造，`explain.py` 只负责重放与渲染，不重新枚举。

## 二、M1 数据与基准（非子命令）

### 2.1 `bench/run.py`

- **输入**：内置程序化定义的 10 编码器 × 7 解码器、链深 2、10 样本 × 8 场景 = 57 例（与 `data/README.md` §1.3.1 同源；出题期"6 个解码器"的描述与冻结 `DECODERS` 不一致，M1 按代码集合更正）。
- **输出**：`bench/out/attr.json`（不入仓）+ 冻结 `bench/golden/attr.json`（入仓，`--check` 逐字节比对）+ 控制台汇总。
- **硬门**：真答案落在候选集内 100%；候选有界；双跑逐字节一致；3.8 / 3.12 重算一致。
- **纪律**：探针数字只作方法可行性证据，不写进 README 首屏、不作代码阈值；链深 3 由 M2 的 `depth3` 块实测并如实登记（候选中位 125 / 最大 241），仍属小样本证据。

### 2.2 fixture 生成器

- `data/fixtures/<module>/gen.py`：固定输入、固定链路、固定文本；`--check` 重生成到临时目录并与入仓 `expect.json` 逐字节比对。
- `expect.json` 只存**输入与期望**，禁止 `observed_*` 字段；期望值可由标准库 `codecs` 独立复算。
- 五类不可逆、三类管道、干净语料基线各一例（清单见 `plan/04-数据计划.md`）。

## 三、M2 `attr` — 归因

### 3.1 CLI

```text
forensics attr --text <s> [--file <path>] [--source-enc enc,...] [--target-enc dec,...]
               [--top N] [--json] [--freq <path>]
```

- `--text` 与 `--file` 互斥；`--file` 按 UTF-8 读取，读不了 → 退出码 2（`file_unreadable`，提示用 `file` 子命令；错误文本不回显绝对路径）。
- `--source-enc` / `--target-enc` 只能收缩冻结集合，不能扩张；非法 codec 名或空项 → 退出码 2（`invalid_codec_subset`）。
- `--top` 默认 5，必须 ≥ 1；`--top 1` 仍返回列表并注明 `truncated_to_top_n`（单候选时为 `single_candidate_in_bounded_search`）。
- `--freq` 为二期可选，当前**明确报错**（`freq_not_implemented`，退出码 2），不伪造语言先验。
- 空输入 → 退出码 2（`empty_input`）。

### 3.2 处理顺序

1. 校验 codec 可用性（不可用 → 退出码 3，`codec_unavailable`）。
2. `paths.enumerate_chains(text, encoders, decoders, max_depth=3)` → 候选链。
3. 无损性硬过滤：逐步逆序重放，任意一步失败即淘汰。
4. `score.rank` → 三层打分 + 固定排序键。
5. 按 `--top` 截断（截断只影响展示，`total_candidates` 始终报完整数量）。
6. 计算置信度区间（`data/README.md` §4.5）。
7. 无候选 → `status="no_candidate"` + `notes=["depth_limit_reached"]`，退出码 1；**不返回空列表冒充成功**。

### 3.3 输出

```json
{
  "status": "candidates",
  "total_candidates": 4,
  "total_chains": 9,
  "candidates": [
    {
      "rank": 1,
      "result": "雅",
      "path": [...],
      "path_string": "...",
      "depth": 1,
      "score": {"readability": 0.8, "depth": 0.5, "language": 0.0, "total": 1.3},
      "confidence": {"lower": 0.31, "upper": 0.42},
      "note": null
    }
  ],
  "criteria": {...}
}
```

- `total_candidates` = 不同结果文本数（`collapse_by_result` 之后）；`total_chains` = 通过无损性硬过滤的链路数。两者均不受 `--top` 影响。
- `result` 是候选链的最终文本（`explain` / `recover` 复用同一 `Chain`，不重新枚举）。
- `note` 取值：`null` / `single_candidate_in_bounded_search` / `no_positive_score` / `truncated_to_top_n`。
- 人读渲染由 `attr.render()` 产出（无颜色、无时间戳、无绝对路径），CLI 通过 `report.emit(..., human=...)` 写出。

### 3.4 测试点

- 候选恒为列表；`--top 1` 不包装成确定解。
- 真答案在候选集内 100%（57 例硬门，M2 已复跑：链深 3 下 57/57）。
- 排序键固定：同一输入双跑逐字节一致；并列时按 `path_string`。
- 非法 codec / `--top 0` / `--text` 与 `--file` 互斥 → 退出码 2 且零文件写入。
- codec 不可用 → 退出码 3（用 monkeypatch 伪造 `codecs.lookup` 失败）。
- 置信度：单候选 `1.0`；全非正分 → `null` + `no_positive_score`（`tests/test_attr.py` 直接喂分项）。

## 四、M3 `explain` — 证明路径

### 4.1 CLI

```text
forensics explain --text <s> (--pick <n> | --all) [--vs <m>] [--json]
```

- `--pick` 从 `attr` 的候选集选第 n 条；`--all` 输出全部候选的证明。二者互斥、必居其一（argparse 互斥组强制）。
- `--vs` 指定对照候选（缺省：top-2 中的另一条——pick 1 对照 2、pick 2 对照 1、其余对照 1）；仅 `--pick` 模式可用（`--all --vs` → 退出码 2）。
- `--pick` / `--vs` 越界 → 退出码 2（`pick_out_of_range` / `vs_out_of_range`，报候选总数）；`< 1` 同样退出码 2。
- 不传 `--text` 而传 `--file` 时与 `attr` 同规则（UTF-8 读取失败 → 退出码 2，提示用 `file` 子命令）。

### 4.2 输出（人读）

```text
candidate 1/323  result='雅'  depth=1  path=encode:cp1252>decode:utf-8
step 1  encode  cp1252  'é›…'  ->  E9 9B 85  OK
step 2  decode  utf-8  E9 9B 85  ->  '雅'  OK
recompute: PASS (2 step(s), every recorded value recomputed)
vs 2  result='茅聸聟'  path=encode:cp1252>decode:latin-1>encode:utf-8>decode:gb18030
  divergence: step 2: op/codec differs: decode:utf-8 vs decode:latin-1
```

机读输出为 `proofs[]`（每条含 `steps[]` + `verify` + `failed_step` + `output` + `divergence`）。

### 4.3 处理顺序（M3 已实现）

1. 先跑一次 `attr.search` 的只读搜索（不落盘、**不重新枚举**），取已排序候选（`Chain` 仍是唯一中间表示）。
2. 对指定候选逐字节重放；每步把重放状态与链路记录（`paths.Step`）比对：记录的输入文本/十六进制必须等于重放状态，`state.encode(codec)` / `state.decode(codec)` 必须等于记录的输出。
3. 第一处不一致停在 `failed_step`（1 起）；失败步带 `failure`（`reason=encode_error|decode_error|input_mismatch|mismatch|state_type|missing_record` + 字节/字符偏移）。
4. 对照：与 `--vs` 候选比较，找出第一处分叉（顺序固定：op/codec → 字节 → 文本 → 链长），输出 `divergence`（`kind=step|bytes|text|depth|none`）；**只陈述差异，不判断哪个更好**。
5. 任一步 `verify=false` → `status="verify_failed"`，退出码 1，`failed_step` 指向具体步；全绿 → `status="ok"`，退出码 0。
6. 无候选 → `status="no_candidate"` + `notes=["depth_limit_reached"]`，退出码 1，`proofs=[]`，不伪造证明。

### 4.4 测试点（M3 已落地：`tests/test_explain.py`）

- 独立重放脚本 `tests/independent_replay.py`（不 import 工具内部状态，只用标准库 + 报告自身 `path`/`steps` 字段）对 `--pick 1` 与 `--all` 全候选复算全绿。
- 故意把链路中一个 codec 名改错（fixture 负例 `decode:gb18030`）→ 该步 `verify=false` 且指向 step 2 / 字节偏移 2；保留记录但换 codec（`decode:latin-1`）→ `mismatch` 同样指向 step 2。
- `--pick` 越界 → 退出码 2 且零文件写入；`--vs` 越界、`--all --vs`、`--pick`+`--all` 同理。
- 双跑逐字节一致；人读输出无绝对路径、无"更好/更准"措辞。
- 对照字节/字符分叉点逐字节断言（`85` vs `84`、`U+203A` vs `U+009B`）。
- codec 不可用 → 退出码 3（monkeypatch）。

## 五、M4 `recover` — 确定性还原 + 不可逆判死

### 5.1 CLI

```text
forensics recover --text <s> --pick <n> [--out <path>] [--json]
```

- 不传 `--pick` → 退出码 2，提示先跑 `attr`；**不接受隐式最佳猜测**。
- `--out` 写文件；默认只写 stdout；**永不覆盖输入**（若 `--out` 与输入同路径 → 退出码 2）。

### 5.2 判定顺序（固定）

1. **不可逆五类**（按固定顺序，先判死）：
   - `U+FFFD` 存在 → `LOST(reason="replacement_char")` + 非法字节偏移；
   - `锟斤拷` 形态 → `LOST(reason="kun_jin_kao")` + `EF BF BD` 重复位置；
   - `烫烫烫` / `屯屯屯` → `NOT_MOJIBAKE(reason="msvc_fill")`；
   - `?` 截断（目标编码无映射且原文可判）→ `LOST(reason="encode_truncated")`；
   - `errors='ignore'` 静默丢失 → `LOST(reason="silent_drop")`。
2. 可还原路径：按 `--pick` 重放 → `RECOVERED` + `verify` 断言。
3. `verify` 失败 → 降级 `LOST(reason="verify_failed")`；**绝不输出未经验证的修复**。

### 5.3 输出

```json
{
  "status": "recovered",
  "recovered": "雅",
  "path_string": "encode:cp1252>decode:utf-8",
  "verify": true,
  "loss": null
}
```

`LOST` 时 `loss` 含 `step` / `offset` / `replaced_with` / `cause`，且输出中不得出现工具自造字符。

### 5.4 测试点

- 五类不可逆各一条单测，断言 `LOST`/`NOT_MOJIBAKE` + 丢失点定位 + 无自造字符。
- `verify` 失败降级测试（monkeypatch 让某步不一致）。
- `--pick` 缺省 / 越界 / `--out` 覆盖输入 → 退出码 2。
- `RECOVERED` 双跑逐字节一致。

## 六、M5 `file` — 原始字节管道

### 6.1 CLI

```text
forensics file --path <path> [--preset csv-excel-win|zip-names|utf16] [--json]
```

### 6.2 处理顺序

1. 只读二进制打开；文件不存在 → 退出码 2。
2. **BOM 嗅探**：UTF-8 / UTF-16LE / UTF-16BE / UTF-32；BOM 与内容矛盾时单列 `bom_conflict`。
3. **UTF-16 奇偶错位**：字节数为奇 / 错位一字节后能否解出合法文本；只报证据，不自动改。
4. **zip 文件名**：`zipfile` 读中央目录（**不解压成员内容**）；`flag_bits & 0x800` 判 UTF-8；无标志时按 CP437 假设对照，列出两种解释。
5. **CSV / Excel-Windows 预设**：`cp1252` / `gbk` / `shift_jis` 候选 + 分隔符嗅探；只报候选，不改文件。
6. 输出 `bom` / `utf16_misalignment` / `zip_names` / `csv_candidates` 分节。

### 6.3 测试点

- 三类 fixture：BOM 冲突、UTF-16 奇偶错位、zip 中文名（带/不带 `0x800` 各一）。
- golden 逐字节一致；重生成 `--check` 一致。
- 输入文件 mtime/内容前后一致（只读）。
- 报告不含绝对路径。

## 七、M5 `scan` — CI 门禁

### 7.1 CLI

```text
forensics scan --dir <path> --baseline <clean-corpus.json> [--format json] [--json]
```

### 7.2 处理顺序

1. 读取基线 JSON（语法错误 → 退出码 2，不写任何输出文件）。
2. 遍历目录，顺序固定（按路径字节序）。
3. 逐文件、逐非空行跑 M1 只读检测路径（不调用 `recover`，不改文件）；命中判据与阈值唯一来源：`data/README.md` §4.8。
4. 命中分类：`new[]` / `baselined[]` / `stale[]`。
5. 输出 JSON（键序固定；无时间/主机名/用户目录），再定退出码：
   - 无 `new` → 0；
   - 有 `new` → 1；
   - 坏输入 → 2（不产出文件）；
   - codec 不可用 → 3。

### 7.3 测试点

- 干净语料：`new` 为空、文件零改动、退出码 0。
- 污染语料：`new` 非空、退出码 1、能定位文件与候选集。
- 基线中指向已不存在文件的条目 → `stale`，不影响退出码。
- 双跑 JSON 逐字节一致；键序固定。

## 八、失败路径矩阵

| 场景 | 子命令 | 退出码 | 是否写文件 |
|---|---|---|---|
| 参数缺失 / 互斥冲突 / 文件不存在 | 全部 | 2 | 否 |
| `--source-enc` / `--target-enc` 非法或试图扩张冻结集合（`invalid_codec_subset`） | attr | 2 | 否 |
| `--file` 非 UTF-8 或不可读（`file_unreadable`） | attr | 2 | 否 |
| `--freq` 传入（`freq_not_implemented`）/ 空输入（`empty_input`） | attr | 2 | 否 |
| `--pick` 越界（`pick_out_of_range`）/ 未给 / `--vs` 越界或与 `--all` 同用 | explain / recover | 2 | 否 |
| 基线 JSON 语法错误 | scan | 2 | 否 |
| codec 不可用 / Python 版本过低 | 全部 | 3 | 否 |
| `attr` 无候选（链深内） | attr | 1 | 否（JSON 可到 stdout） |
| `recover` 判 `LOST` | recover | 1 | `--out` 时写 |
| `explain` 某步 verify=false | explain | 1 | 否 |
| `scan` 有 `new` | scan | 1 | 写 JSON（若指定） |
| 骨架期未实现模块 | 全部 | 4 | 否 |

> 退出码 4 是**骨架期专用**（`EXIT_NOT_READY`）：对应模块落地后整项退役——改 CLI、改测试、改文档退出码表三处同步（常量本身保留到 M5 最后一个子命令退役）。M2 起 `attr`、M3 起 `explain` 不再返回 4；`recover` / `file` / `scan` 仍在骨架期。

## 九、接口稳定性

- JSON `schema` 字段在 v0.1.0 固定为 `mojibake-forensics/1`；字段只增不改、不改语义。
- 新增字段必须同时在 `README.md` 字段说明与 `tests/` 中登记。
- `criteria` 与 `notes` 是输出的一部分，不允许省略。
