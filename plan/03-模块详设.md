# 03 · 模块详设

> 五个子命令的接口、数据结构、处理顺序、失败路径与测试点。所有数值口径引用 `data/README.md` §四；本文件不另立第二套。退出码语义见 §四.7 与 `src/mojibake_forensics/report.py`。

## 一、公共契约

### 1.1 输出形态

- **人读**：默认写 stdout，稳定、无颜色、无时间戳。
- **机读**：`--json` 输出规范 JSON（`sort_keys=True`, `ensure_ascii=False`, `indent=2`, LF, 结尾换行）。
- **错误**：结构化错误写 stderr；`--json` 时同时输出 `{"status":"error","code":...,"message":...}` 到 stdout（退出码 2 的坏输入除外：不写任何文件，stdout 只放错误 JSON）。
- **候选恒为列表**：任何单候选都包在 `candidates` 数组里，并带 `note`；禁止"已确定 / 正确编码是 / 修复成功"。

### 1.2 公共字段

```json
{
  "schema": "mojibake-forensics/1",
  "tool_version": "0.1.0.dev0",
  "python_version": "3.8.18",
  "status": "candidates | no_candidate | recovered | lost | not_mojibake | ok | error | not_ready",
  "notes": [],
  "criteria": {
    "encoders": ["utf-8", "..."],
    "decoders": ["utf-8", "..."],
    "max_depth": 3
  }
}
```

`criteria` 是"结论口径"的一部分：每次输出都必须带，提醒读者候选是"给定集合与链深下的全部无损可能"，不是事实真相。

### 1.3 链路结构 `Chain`

```json
{
  "path": [{"op": "encode", "codec": "cp1252"}, {"op": "decode", "codec": "utf-8"}],
  "path_string": "encode:cp1252>decode:utf-8",
  "depth": 1,
  "steps": [
    {"index": 1, "op": "encode", "codec": "cp1252",
     "input": "é›…", "output_hex": "65 C3 8B E2 80 A6", "ok": true},
    {"index": 2, "op": "decode", "codec": "utf-8",
     "input_hex": "65 C3 8B E2 80 A6", "output": "雅", "ok": true}
  ]
}
```

- `depth` = 链中 `decode` 的步数（`data/README.md` §4.2）。
- 字节统一大写十六进制、单空格分组。
- `steps` 由 `paths.py` 构造，`explain.py` 只负责重放与渲染，不重新枚举。

## 二、M1 数据与基准（非子命令）

### 2.1 `bench/run.py`

- **输入**：内置程序化定义的 10 编码器 × 6 解码器、链深 2、10 样本 × 8 场景 = 57 例（与 `data/README.md` §1.3 同源）。
- **输出**：`bench/out/attr.json`（不入仓）+ 控制台汇总。
- **硬门**：真答案落在候选集内 100%；候选有界；双跑逐字节一致。
- **纪律**：探针数字只作方法可行性证据，不写进 README 首屏、不作代码阈值；链深 3 未实测，`notes` 如实登记。

### 2.2 fixture 生成器

- `data/fixtures/<module>/gen.py`：固定输入、固定链路、固定文本；`--check` 重生成到临时目录并与入仓 `expect.json` 逐字节比对。
- `expect.json` 只存**输入与期望**，禁止 `observed_*` 字段；期望值可由标准库 `codecs` 独立复算。
- 五类不可逆、三类管道、干净语料基线各一例（清单见 `plan/04-数据计划.md`）。

## 三、M2 `attr` — 归因

### 3.1 CLI

```text
forensics attr --text <s> [--file <path>] [--source-enc enc,...] [--target-enc dec,...]
               [--top N] [--json] [--freq <path>]
```

- `--text` 与 `--file` 互斥；`--file` 按 UTF-8 读取，读不了转 M4 错误路径（退出码 2，提示用 `file` 子命令）。
- `--source-enc` / `--target-enc` 只能收缩冻结集合，不能扩张；非法 codec 名 → 退出码 2。
- `--top` 默认 5，必须 ≥ 1；`--top 1` 仍返回列表并注明 `single_candidate_in_bounded_search`。

### 3.2 处理顺序

1. 校验 codec 可用性（不可用 → 退出码 3，`codec_unavailable`）。
2. `paths.enumerate(text, encoders, decoders, max_depth=3)` → 候选链。
3. 无损性硬过滤：逐步逆序重放，任意一步失败即淘汰。
4. `score.rank` → 三层打分 + 固定排序键。
5. 按 `--top` 截断（截断只影响展示，`total_candidates` 始终报完整数量）。
6. 计算置信度区间（`data/README.md` §4.5）。
7. 无候选 → `status="no_candidate"` + `notes=["depth_limit_reached"]`，退出码 1；**不返回空列表冒充成功**。

### 3.3 输出

```json
{
  "status": "candidates",
  "total_candidates": 4,
  "candidates": [
    {
      "rank": 1,
      "path": [...],
      "path_string": "...",
      "depth": 1,
      "score": {"readability": 0.8, "depth": 0.5, "language": 0.0, "total": 1.3},
      "confidence": {"lower": 0.31, "upper": 0.42},
      "note": null
    }
  ],
  "criteria": {...}
}
```

### 3.4 测试点

- 候选恒为列表；`--top 1` 不包装成确定解。
- 真答案在候选集内 100%（57 例硬门，M2）。
- 排序键固定：同一输入双跑逐字节一致；并列时按 `path_string`。
- 非法 codec / `--top 0` / `--text` 与 `--file` 互斥 → 退出码 2 且零文件写入。
- codec 不可用 → 退出码 3（用 monkeypatch 伪造 `codecs.lookup` 失败）。

## 四、M3 `explain` — 证明路径

### 4.1 CLI

```text
forensics explain --text <s> --pick <n> [--all] [--vs <m>] [--json]
```

- `--pick` 从 `attr` 的候选集选第 n 条；`--all` 输出全部候选的证明。
- `--vs` 指定对照候选（默认 top-2），输出逐字节分叉点。
- 不传 `--text` 而传 `--file` 时与 `attr` 同规则。

### 4.2 输出（人读）

```text
step 1  encode  cp1252  'é›…'  →  65 C3 8B E2 80 A6
step 2  decode  utf-8   →  '雅'
复算   '雅'.encode('utf-8') == b'\xe9\x9b\x85'  ✅
```

机读输出为 `steps[]` + `verify: true|false` + `failed_step: null|n` + `divergence`。

### 4.3 处理顺序

1. 先跑 `attr` 的只读枚举（不落盘），取候选。
2. 对指定候选逐字节重放；每步记录输入/输出。
3. 独立复算断言：`output.encode(codec)` 或 `bytes.decode(codec)` 与本步记录一致。
4. 对照：与 `--vs` 候选比较，找出第一处字节/链路分叉，输出 `divergence`；**只陈述差异，不判断哪个更好**。
5. 任一步 `verify=false` → 退出码 1，`failed_step` 指向具体步。

### 4.4 测试点

- 独立重放脚本（不 import 工具内部状态）对 `verify` 全绿。
- 故意把链路中一个 codec 名改错 → 该步 `verify=false` 且指向具体 step。
- `--pick` 越界 → 退出码 2。
- 双跑逐字节一致。

## 五、M4 `recover` — 确定性还原 + 不可逆判死

### 5.1 CLI

```text
forensics recover --text <s> --pick <n> [--out <path>] [--json]
```

- 不传 `--pick` → 退出码 2，提示先跑 `attr`；**不接受隐式最佳猜测**。
- `--out` 写文件；默认只写 stdout；**永不覆盖输入**（若 `--out` 与输入同路径 → 退出码 2）。

### 5.2 判定顺序（固定）

1. **不可逆五类**（按固定顺序，先判死）：
   - `U+FFFD` 存在 → `LOST(reason="replacement_char")` + 非法字节偏移；
   - `锟斤拷` 形态 → `LOST(reason="kun_jin_kao")` + `EF BF BD` 重复位置；
   - `烫烫烫` / `屯屯屯` → `NOT_MOJIBAKE(reason="msvc_fill")`；
   - `?` 截断（目标编码无映射且原文可判）→ `LOST(reason="encode_truncated")`；
   - `errors='ignore'` 静默丢失 → `LOST(reason="silent_drop")`。
2. 可还原路径：按 `--pick` 重放 → `RECOVERED` + `verify` 断言。
3. `verify` 失败 → 降级 `LOST(reason="verify_failed")`；**绝不输出未经验证的修复**。

### 5.3 输出

```json
{
  "status": "recovered",
  "recovered": "雅",
  "path_string": "encode:cp1252>decode:utf-8",
  "verify": true,
  "loss": null
}
```

`LOST` 时 `loss` 含 `step` / `offset` / `replaced_with` / `cause`，且输出中不得出现工具自造字符。

### 5.4 测试点

- 五类不可逆各一条单测，断言 `LOST`/`NOT_MOJIBAKE` + 丢失点定位 + 无自造字符。
- `verify` 失败降级测试（monkeypatch 让某步不一致）。
- `--pick` 缺省 / 越界 / `--out` 覆盖输入 → 退出码 2。
- `RECOVERED` 双跑逐字节一致。

## 六、M5 `file` — 原始字节管道

### 6.1 CLI

```text
forensics file --path <path> [--preset csv-excel-win|zip-names|utf16] [--json]
```

### 6.2 处理顺序

1. 只读二进制打开；文件不存在 → 退出码 2。
2. **BOM 嗅探**：UTF-8 / UTF-16LE / UTF-16BE / UTF-32；BOM 与内容矛盾时单列 `bom_conflict`。
3. **UTF-16 奇偶错位**：字节数为奇 / 错位一字节后能否解出合法文本；只报证据，不自动改。
4. **zip 文件名**：`zipfile` 读中央目录（**不解压成员内容**）；`flag_bits & 0x800` 判 UTF-8；无标志时按 CP437 假设对照，列出两种解释。
5. **CSV / Excel-Windows 预设**：`cp1252` / `gbk` / `shift_jis` 候选 + 分隔符嗅探；只报候选，不改文件。
6. 输出 `bom` / `utf16_misalignment` / `zip_names` / `csv_candidates` 分节。

### 6.3 测试点

- 三类 fixture：BOM 冲突、UTF-16 奇偶错位、zip 中文名（带/不带 `0x800` 各一）。
- golden 逐字节一致；重生成 `--check` 一致。
- 输入文件 mtime/内容前后一致（只读）。
- 报告不含绝对路径。

## 七、M5 `scan` — CI 门禁

### 7.1 CLI

```text
forensics scan --dir <path> --baseline <clean-corpus.json> [--format json] [--json]
```

### 7.2 处理顺序

1. 读取基线 JSON（语法错误 → 退出码 2，不写任何输出文件）。
2. 遍历目录，顺序固定（按路径字节序）。
3. 逐文件跑 M1 只读检测路径（不调用 `recover`，不改文件）。
4. 命中分类：`new[]` / `baselined[]` / `stale[]`。
5. 输出 JSON（键序固定；无时间/主机名/用户目录），再定退出码：
   - 无 `new` → 0；
   - 有 `new` → 1；
   - 坏输入 → 2（不产出文件）；
   - codec 不可用 → 3。

### 7.3 测试点

- 干净语料：`new` 为空、文件零改动、退出码 0。
- 污染语料：`new` 非空、退出码 1、能定位文件与候选集。
- 基线中指向已不存在文件的条目 → `stale`，不影响退出码。
- 双跑 JSON 逐字节一致；键序固定。

## 八、失败路径矩阵

| 场景 | 子命令 | 退出码 | 是否写文件 |
|---|---|---|---|
| 参数缺失 / 互斥冲突 / 文件不存在 | 全部 | 2 | 否 |
| `--pick` 越界 / 未给 | explain / recover | 2 | 否 |
| 基线 JSON 语法错误 | scan | 2 | 否 |
| codec 不可用 / Python 版本过低 | 全部 | 3 | 否 |
| `attr` 无候选（链深内） | attr | 1 | 否（JSON 可到 stdout） |
| `recover` 判 `LOST` | recover | 1 | `--out` 时写 |
| `explain` 某步 verify=false | explain | 1 | 否 |
| `scan` 有 `new` | scan | 1 | 写 JSON（若指定） |
| 骨架期未实现模块 | 全部 | 4 | 否 |

> 退出码 4 是**骨架期专用**（`EXIT_NOT_READY`）：对应模块落地后整项退役——删常量、改 CLI、改测试、改文档退出码表四处同步。M2–M5 完成时不得残留。

## 九、接口稳定性

- JSON `schema` 字段在 v0.1.0 固定为 `mojibake-forensics/1`；字段只增不改、不改语义。
- 新增字段必须同时在 `README.md` 字段说明与 `tests/` 中登记。
- `criteria` 与 `notes` 是输出的一部分，不允许省略。
