# 02 · 架构与技术选型

> 本文件只回答"系统怎么分层、凭什么这么选"。数值口径一律以 `data/README.md` §四为准；模块接口以 `plan/03-模块详设.md` 为准。

## 一、总体分层

```text
┌──────────────────────────────────────────────────────────────┐
│  CLI 层            src/mojibake_forensics/cli.py              │
│  argparse 子命令、参数校验、退出码映射、stdout/stderr 分流     │
├──────────────────────────────────────────────────────────────┤
│  判定层            attr.py / explain.py / recover.py          │
│  归因枚举、证明重放、不可逆判死；只读、无副作用                 │
├──────────────────────────────────────────────────────────────┤
│  管道层            file.py / scan.py                          │
│  原始字节诊断 / 目录门禁；只读、不写回、输出机读 JSON           │
├──────────────────────────────────────────────────────────────┤
│  核心层            paths.py / score.py / report.py            │
│  链路枚举与无损性过滤 / 三层打分 / 规范 JSON 与退出码            │
├──────────────────────────────────────────────────────────────┤
│  口径层            codecs_table.py                            │
│  编码器/解码器集合、链深上限、codec 可用性探测（唯一冻结点）      │
├──────────────────────────────────────────────────────────────┤
│  底层              Python 标准库 codecs / encodings / zipfile  │
│  零外部数据、零网络、零模型                                    │
└──────────────────────────────────────────────────────────────┘
```

**依赖方向只能自上而下**：底层不得 import 判定层；`file` / `scan` 不得调用 `recover`。这条约束由测试用 AST 扫描守门（M5 落地）。

### 1.1 为什么是"核心层 + 五个薄壳"

- 候选枚举、无损性过滤、打分、排序键是**全项目唯一真值路径**。如果五个子命令各写一份，必然出现"attr 的候选与 explain 重放的不是同一条链"——证明可复算就失效了。
- 因此 `paths.py` 产出的 `Chain` 是**唯一中间表示**；`attr` 只是它的排序视图，`explain` 只是它的逐步重放视图，`recover` 只是"按 `--pick` 选一条后判定"的视图。
- `file` / `scan` 走独立入口（原始字节 / 目录），但共用 `report.py` 的规范 JSON 与退出码。

### 1.2 数据流（字符串入口）

```text
--text/--file
   │
   ▼
[codecs_table] 冻结 ENCODERS / DECODERS / MAX_DEPTH，探测可用性
   │
   ▼
[paths.enumerate_chains] encode/decode 交替枚举（深度 ≤ 3）
   │  每步失败（UnicodeEncodeError/UnicodeDecodeError）→ 丢弃该边
   ▼
[paths.verify_lossless] t2.encode(last_decoder) == bytes 等逐步逆序重放
   │  不满足 → 淘汰
   ▼
[score.rank] 三层打分 + 排序键 (-score_total, depth, path_string)
   │
   ▼
[report] 候选列表 + 置信度区间 + 口径声明（永不单解包装）
```

## 二、技术选型

| 项 | 选择 | 理由 / 弃选 |
|---|---|---|
| 语言 | Python ≥ 3.8 | 标准库 `codecs` 编码表随解释器冻结；本机实测 3.8.8 与 3.12 双通道。3.8 是底线，代码不得使用 3.9+ 语法 |
| 依赖 | **零第三方运行时依赖** | 编码表、zip 中央目录、CSV 嗅探、JSON 全部标准库；零网络、零模型是产品红线 |
| 打包 | `pyproject.toml` + setuptools（src layout） | `pip install -e .` 即得 `forensics` 命令；sdist/wheel 可离线构建 |
| CLI | `argparse` | 标准库；退出码语义显式映射（见 `report.py`）；不用 click/typer 以免多一层依赖 |
| JSON | `json.dumps(sort_keys=True, ensure_ascii=False, indent=2)` + LF + 结尾换行 | 单点序列化，双跑逐字节一致；中文不转义 |
| 测试 | `pytest`（开发期依赖，非运行时） | 本机 3.8 有 pytest 7.4、3.12 有 pytest 8.4；CI 安装 `.[dev]` |
| 布局门 | `tools/check_sprint_layout.py`（纯标准库） | 与主项目同语言，CI 不需要 Node；判据集对齐 skill 模板 |
| 基准 | `bench/run.py`（**M1 已落地；M2 已复跑硬门并追加 `depth3` 块**） | 57 例程序化生成 + 复算；`bench/golden/attr.json` 入仓，`bench/out/` 不入仓 |
| 文档 | 中文 Markdown | 目标读者为中文开发者；CLI 错误信息中文 + 稳定错误码 |

### 2.1 弃选

- **Rust / Go 重写**：编码表要自带，且与 Python 标准库行为对齐成本高；本题的卖点是"可复算"，不是性能。
- **调用 chardet / charset-normalizer**：它们回答的是另一个问题（`bytes → 编码名`），且会引入外部依赖与版本漂移。本工具只在内部枚举标准库 codec。
- **Web / GUI / 服务端**：纯本地 CLI 是唯一交付形态；云分析违反隐私红线。
- **原地修复 / 批量改名**：破坏证据，永不进判定路径。

## 三、构建与运行

### 3.1 开发环境

```bash
py -3.8 -m venv .venv
.venv/Scripts/python -m pip install -e ".[dev]"     # Windows Git Bash
# 或：python -m pip install -e ".[dev]"
```

> 本机 `python` 是商店占位符，统一用 `py`；脚本与测试建议 `py -X utf8` 运行（中文控制台）。CI 内显式设置 `PYTHONUTF8=1`。

### 3.2 构建

```bash
py -m build            # 需开发期安装 build；产物进 dist/
py -m pip install dist/mojibake_forensics-0.1.0.dev0-py3-none-any.whl
```

- 版本号单一来源：`src/mojibake_forensics/__init__.py` 的 `__version__` 与 `pyproject.toml` 的 `version` **同一次提交一起改**；发布期由测试断言两处一致（M6）。
- sdist 必须自足：`MANIFEST.in` 白名单覆盖 `data/fixtures/**` 的生成物；构建必须在 `git archive <tag>` 的干净目录里做（M6）。

### 3.3 验证入口

```bash
python tools/check_sprint_layout.py      # 布局门（方法论装订）
python -m pytest -q                      # 单元 + 常驻测试
python tools/check_layout_mutations.py   # 布局门变异验证（临时目录，不改工作树）
python bench/run.py --check              # M1 起：57 例基准逐字节比对
forensics --help
```

## 四、确定性设计

| 风险 | 处置 |
|---|---|
| 字典/集合迭代序 | 枚举结果先落列表，再按 `(-score_total, depth, path_string)` 排序；JSON `sort_keys=True` |
| 系统 locale | 禁止 `locale.getpreferredencoding()` 参与判定；文件读取显式 `encoding="utf-8"` |
| 时钟 / 主机名 / 绝对路径 | 报告不含时间、主机名、用户目录；文件路径只输出调用方给的相对/原样路径 |
| 浮点比较 | 打分只用于排序与展示；输出保留固定小数位（6 位），排序比较用定点整数化后的值 |
| 双跑差异 | `attr` / `explain` / `file` / `scan` 各配"同输入双跑逐字节一致"测试 |

## 五、安全与隐私

- 纯本地、零网络：代码中不得出现 `requests` / `urllib.request` / socket 调用（M5 AST 守门）。
- 不采集真实样本：全部 fixture 程序化合成；`samples/`、`_private/` 在 `.gitignore` 中。
- 报告不写绝对路径、主机名、用户名；`scan` 的 JSON 只含相对路径。
- 不写回输入文件：`file` / `scan` 只读打开；`recover` 只写 stdout 或 `--out`。
