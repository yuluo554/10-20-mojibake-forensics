> - **性质**：不参赛项目题（无赛事锚点；含金量锚点 = 编码表冻结标准 + 每一步 encode/decode 可复算的字节证明 + 真实需求原话）
> - **目标产出**：仓库 `10-20-mojibake-forensics`（MojibakeForensics / 乱码尸检 · proof-carrying 编码归因），发布 GitHub **公开仓库**，署名 yuluo554
> - **版本史**：v1 2026-10-20（初稿定稿；查证基准日 2026-10-20）
> - **交付形态**：**纯本地 Python CLI（标准库编码表，零外部数据、零网络、无模型）**。唯一形态，不设备选：所有结论都由 Python 标准库内置的编解码器复算得出，不下载编码表、不调用任何网络接口、不加载任何模型权重。
> - **定位宣言**："ftfy 官方文档明确把 CJK 编码排除在外；检测器（chardet / uchardet / charset-normalizer）只回答'这是什么编码'，不回答'**已经解坏的 str 是被哪一步转坏的**'。本工具做乱码尸检：输出**有界候选集 + 每一步 encode/decode 的字节证明 + 哪一步不可逆**，**永不假装猜出唯一答案**——这是与所有'自动修乱码'工具的立场差异。"

## 一、介绍

### 1.1 痛点

乱码从来不是一个"选错下拉框"的小问题，它是**信息已经丢掉一部分**的事故现场。三类人每天在同一个坑里反复：

1. **跨平台开发者**：Windows 默认代码页的文件、Excel 导出的 CSV、zip 里被打成 CP437 的中文/日文文件名，同一个字符串在不同环节各被转坏一次。
2. **数据工程师 / 字幕翻译 / 老系统迁移者**：手里的内容已经是 `str`（Python 里"看起来是文本"），但内容是 `é›…é›…` 这样的东西——**不是字节问题，是有人在你之前做过一次错误的 decode**。
3. **CI 维护者**：PR 里混进一段乱码，评审看不出来、测试不会失败，等用户看到才知道。

现有工具在第一步就分道扬镳：

- **检测器**（chardet / uchardet / charset-normalizer / chardetng）回答"**这串字节**最可能是什么编码"。它们吃的是 `bytes`。
- **修复器**（ftfy）吃的是 `str`，做的是"把看起来像 mojibake 的字符串还原"，但它的先验是**保守不动**：判不准就不动，且不告诉你它考虑过哪些可能。

中间那一层是空的：**手里已经是一个解坏的 `str`，它到底是"UTF-8 被当成 CP1252 读了"、"GBK 被当成 Latin-1 读了"，还是"本来就是这些字符"？如果是前者，是哪一步转坏的、还能不能回去？**

### 1.5 不可逆类：必须判死，不许猜

以下五类**根本不是"可以还原的乱码"**，而是**字节已经丢了**。任何"自动修乱码"工具在这里猜字，都会给出自信的错误答案：

| 类别 | 成因 | 本工具的结论 |
|---|---|---|
| `锟斤拷` | `EF BF BD`（U+FFFD）重复被 GBK 读回 | **已丢失**，定位"原始字节在哪一步被替换成 U+FFFD" |
| `烫烫烫` / `屯屯屯` | MSVC Debug 用 `0xCC` / `0xCD` 填充未初始化栈 | **不是乱码**（是填充值被当文本读），判"非编码事故" |
| `?` 截断 | 目标编码无该字符映射 → 编码器写入 `?` | **已丢失**，定位截断发生在 encode 方向 |
| `U+FFFD` | decode 遇非法序列 → 替换符 | **已丢失**，给出非法字节偏移 |
| （第五类）静默空串/丢字符 | 编码器 `errors='ignore'` | **已丢失**，指出信息量为零 |

## 二、任务要求

首期 **5 个模块**，每模块写清 **输入 / 输出 / 确定性纪律 / 验收**。所有模块共享 `data/README.md` §四的**数值口径**（编码器集合、解码器集合、链深上限、打分权重、置信度口径、误改率为零的判定、退出码），**不得在代码或文案中另立第二套口径**。

### 模块 M1 `attr` — 归因（核心）

- **输入**：一个已解坏的字符串（`--text`）、或一个 UTF-8 文本文件（`--file`，按 UTF-8 读取；读不了就走 M4）；可选 `--source-enc` / `--target-enc` 收缩编码器 / 解码器集合。
- **输出**：**top-N 候选**（默认 N=5，`--top` 可调），每个候选含：
  - `path`：`[{"op":"encode","codec":"cp1252"},{"op":"decode","codec":"utf-8"}]` 形式的链路；
  - `bytes`：链路每一步的中间字节（十六进制）；
  - `score`：三层打分的分项（可读性 / 链深 / 语言先验）与合计；
  - `confidence`：归一化后的**区间**（见 §四口径：候选间相对置信度，不是一个假装精确的概率）。
- **引擎**：
  1. **枚举**：`encode(codec)` / `decode(codec)` 交替组合，**链深 ≤ 3**，编码器集合 / 解码器集合由 `data/README.md` §四冻结；遇到 `UnicodeEncodeError` / `UnicodeDecodeError` 的边直接丢弃（不静默用 `errors='replace'`）。
  2. **无损性硬过滤**：对每个候选链，把结果 `t2` 重新按链路**反向**编码回原始字节，断言 `t2.encode(decoder) == bytes`（此处 `decoder` 指链路最后一次 decode 的编码器）。**不满足者直接淘汰**——这是候选集"不漏真答案"的保证（探针 57/57 支撑）。
  3. **三层打分**（权重在 §四单点定义）：
     - ①**可读性**：解码结果中的控制字符、PUA（`U+E000–U+F8FF`）、`U+FFFD`、代理项、半角片假名、制表符 → 负分；CJK 常用字 / 拉丁可见字符 → 正分；
     - ②**链深偏好**：浅层优先（探针：加此条后真答案排第一从 79% → 93%）；
     - ③**语言先验**：可选词频表（**默认关闭**，见 `data/README.md` §二许可边界）。
  4. **永不返回单解，除非 N=1**：输出恒为列表；即使只有一个候选也写明 `candidates=1`，不把它包装成"确定了"。
- **确定性纪律**：候选排序键固定为 `(-score, depth, path_string)`；同一输入两次运行输出逐字节一致；不读系统 locale（`locale.getpreferredencoding()` 不参与任何判定）；不依赖 `sys.stdin` 编码。
- **验收**：用 `bench/run.py` 的 57 例探针口径可复现——**真答案落在候选集内 100%**（硬门），候选中位规模与探针同量级（**不锁具体数字**，只锁"有界"）；同一输入双跑逐字节一致。

### 模块 M2 `explain` — 证明路径（每条结论可独立重放）

- **输入**：M1 的一个（或 `--all` 全部）候选路径 + 原始字符串。
- **输出**：每一步的**可重放证明**：
  ```
  step 1  encode  cp1252  'é›…'  →  65 C3 8B E2 80 A6   （字节转储）
  step 2  decode  utf-8   →  '雅'
  复算   '雅'.encode('utf-8') == b'\xe9\x9b\x85'  ✅
  ```
  外加 **"为什么不是另一个候选"的对照**：与 top-2（或 `--vs` 指定）逐字节列出分叉点。
- **引擎**：把 M1 的链路结构化成可执行断言序列；每条路径附 `verify` 布尔与失败点位置；对照部分只陈述字节差异，不做"哪个更好"的语义断言。
- **确定性纪律**：输出不含时间、路径、主机名；字节统一大写十六进制、单空格分组；对照顺序按 M1 排序键；同一路径双跑逐字节一致。
- **验收**：每条路径**可被独立重放校验**——`explain` 输出的复算断言，用一段不依赖本工具内部状态的独立脚本重跑必须全绿（测试里就是独立脚本）；故意把链路中的一个 codec 名改错 → 该步 `verify=false` 且指向具体 step。

### 模块 M3 `recover` — 确定性还原 + 不可逆判死

- **输入**：字符串 + M1 的指定候选（`--pick <n>`；不给则要求先跑 `attr`，**不接受隐式"最佳猜测"**）。
- **输出**：两种互斥结果：
  - `RECOVERED`：还原后的字符串 + 使用的链路 + 验证断言；
  - `LOST`：判"已丢失"，附**丢失点定位**（哪一步、哪个字节/偏移、被替换成什么），并给出该类的成因说明。**不猜字、不补全。**
- **引擎**：五类不可逆直接判死——`锟斤拷`（`EF BF BD` 重复被 GBK 读回）、`烫烫烫`/`屯屯屯`（MSVC `0xCC`/`0xCD` 填充，**根本不是乱码**）、`?` 截断、`U+FFFD`、`errors='ignore'` 造成的静默丢失。
- **确定性纪律**：判定顺序固定（先判不可逆，再判可还原）；同类判定不看上下文猜测；`RECOVERED` 必须附 `verify` 断言，断言失败则降级为 `LOST(reason=verify_failed)`，**绝不输出未经验证的"修复"**。
- **验收**：**五类各有单测**，每类断言 `LOST` + 丢失点定位正确 + **不产生替换字符**（断言输出中不含任何本工具自行编造的字符）。

### 模块 M4 `file` — 原始字节管道

- **输入**：文件路径（`--path`）+ 可选预设（`--preset csv-excel-win` 等）。
- **输出**：管道诊断报告：
  - **BOM 嗅探**（UTF-8 / UTF-16LE / UTF-16BE / UTF-32，及"BOM 与内容自相矛盾"）；
  - **UTF-16 奇偶错位**（字节数奇、错位一字节后能否解出合法文本）；
  - **zip 文件名**（`flag_bits & 0x800` 判 UTF-8 标志；无标志时按 **CP437 假设**对照，列出两种解释）；
  - **CSV / Excel-Windows 预设**（`cp1252`/`gbk`/`shift_jis` 候选 + 分隔符嗅探，只报候选不改文件）。
- **引擎**：只读打开、二进制读取；zip 用标准库 `zipfile` 读中央目录（**不解压成员内容**）；预设是一组**具名候选集合**，不是"自动修复"。
- **确定性纪律**：**不写回原文件**（本题不做原地修复）；报告不落绝对路径（只留给定时可复现的相对名或用 `--json` 输出到 stdout）；同一文件双跑一致。
- **验收**：**三类高频管道各有 fixture**——BOM 冲突、UTF-16 奇偶错位、zip 中文名（带/不带 UTF-8 标志各一）。fixture 生成脚本可重建、golden 逐字节一致。

### 模块 M5 `scan` — CI 门禁

- **输入**：目录 + `--baseline <clean-corpus.json>`（干净语料基线）+ `--format=json`。
- **输出**：批量结果 + **退出码**（见 §四）+ **机器可读 JSON**（供 CI 消费）。
- **引擎**：逐文件跑 M1 的**只读检测路径**（不调用 `recover`，不改任何文件）；命中即报"疑似乱码 + 候选集"；与基线对照区分"新增 / 已登记"。
- **确定性纪律**：遍历顺序固定（按路径字节序）；JSON 键序固定；不写扫描时刻、不写主机名、不写用户目录；**退出码语义只在 §四定义一次**。
- **验收**：**干净文本语料上零改动、零报告**（误报防线：用公开中文文本**只提取统计、不入仓原文**构造基线，口径见 `data/README.md` §三）；含乱码的语料 → 退出码非 0 且 JSON 里能定位到文件与候选集。

### 扩展项（明确列二期，不进首期判定路径）

- **D-2 Unicode 安全扫描**（bidi / 同形异义 / 不可见字符）：二期。理由见 §六——已有 `anti-trojan-source` 等覆盖且已产品化。
- **词频表驱动的语言先验**：默认关闭，二期做成可选数据包（许可边界见 `data/README.md` §二）。
- **原地修复**：**永不进判定路径**（会破坏证据；本题的立场是"尸检"，不是"整容"）。

## 六、边界与非目标

- **不做 Unicode 安全扫描（首期）**：`anti-trojan-source` 90★ + eslint 插件 80★ + bidichk 42★ + glassworm-hunter 30★ 已覆盖 bidi；Aikido / CrowdStrike 已产品化。做它是重复劳动，且会把"乱码归因"这一窄缝冲淡。列二期扩展项 D-2。
- **不做通用 homoglyph / IDN 库**：dnstwist 5761★ / codebox-homoglyph 638★ / decancer 131★ 已商品化；中文形近表需自建（`confusables.txt` 里 CJK 源项仅 410 条，数据工程超一周），收益与本题主线无关。
- **不重做 charset 检测器**：chardet 2680★ 是红海，且检测器回答的是另一个问题（`bytes → 编码名`）。本题只在本工具内部需要"字节候选"时复用标准库编解码器。
- **不做云服务 / 上传 / 遥测**：隐私红线 = **纯本地、零网络**。任何"把文本发到服务器分析"的设计均不采用。报告不写绝对路径、不写主机名、不写用户名。
- **不做原地修复**：`recover` 只输出到 stdout / `--out` 指定文件，**永不覆盖输入**。理由是尸检立场：破坏原始证据就没有第二次复算。
- **不承诺唯一解**：这是产品立场，不是缺陷。候选集恒为列表，置信度恒为区间；文档、输出 schema、README 三处表述必须一致。
- **链深上限 3**：深度 3 的候选规模已由 M2 实测（候选中位 125 / 最大 241，真答案入集 57/57），但仍是小样本证据、**不作阈值**；超过上限明确报 `depth_limit_reached`，不静默截断。
- **首期范围限定**：CJK（`gb18030` / `gbk` / `big5` / `shift_jis` / `euc-jp` / `euc-kr`）优先，西文（`cp1252` / `latin-1`）作为通道参与但**不做全量代码页覆盖**。
- **品牌隔离**：本系列其他本地工具不得在文档、代码、提交信息中被提及。
- **结论纪律**：`attr` 的候选是"在给定编码集合与链深上限下的**全部无损可能**"，不等于"事实真相"；报告必须同时输出候选集与该口径，由人判断。
